# AI 付箋を作業指示にし、質問はチャットに寄せる

今の AI 付箋は、Web だけを使える Claude に質問して、答えを付箋に持たせる（`POST /api/claude/answer`）。
これを、Claude Code に作業を頼む入口に替える。質問は、チャットの入力欄の「質問」で聞き、答えは会話の欄に出す。

## わけ（ユーザーと話して決めた）

- 付箋は、作業する物の隣に置け、頼んだことと結果がキャンバスに残る（ログになる）。作業の指示に向く
- 質問は会話になりやすく、たいてい残す要がない。チャットに向く
- 「そうじゃなくて」と直したいときは、付箋に注意事項を書き足して、送り直す（付箋の文が、いつも全部入りの指示になる）
- 許可（Claude Code が Bash などで尋ねてきたとき）は、質問のタブ（下で「作業」のタブにする）の許可のボタンで答える
- 付箋から会話へは「チャットで続ける」のボタン 1 つで移れる
- 安全：個人で使うので、付箋から Bash やファイルの書き換えを頼めてよい（複数の人で使うようになったら考え直す）
- チャットのツールは、入力欄の「会話｜質問」で選ぶ。会話は今のジョブと同じ（ファイル・Bash・canvcode の MCP・サブエージェント・スキル。auto mode で判定）、
  質問は Web だけ（今の `/api/claude/answer`）

## 決めたこと

1. 付箋の作業は、今の会話のジョブ（`apps/server/src/claude/jobs.ts`）で動かす。使えるツールと許し方は、会話と同じ
2. 送り直すときは、新しい会話で始める。前の会話は引き継がず、前の作業の記録（変えたノード・書いたファイル・最後の報告）を材料として渡す
   （付箋の文だけで結果が決まり、前のやり方に引きずられないように。ただ、前の変更はキャンバスやファイルに残っているので、それは知らせる）
3. 送り直すとき、「前の変更を戻してから送る」も選べる（キャンバスの変更だけ。`agent_ops` の取り消し。Bash とファイルの変更は戻せないので、記録として渡す）
4. 残す機能：「Canvasに残す」「付箋に切り出す」（会話の答え → 付箋）「続けて聞く」（→「続けて頼む」）「関連する付箋」
5. 前に Q&A で答えた付箋の答えは、今のまま読める
6. チャットの「質問」の答えは、会話の欄に出す。「会話｜質問」は、送っても戻さない
7. 実装は、ほかのセッションの `koukunpadi1250/ai-note-pick-text`（PDF の文字をなぞって添える）が統合ブランチに入ってから始める

## 作り

### A. サーバー：付箋の作業（`jobs.ts`・`store.ts`・`http.ts`）

- `POST /api/claude/jobs` に `note: { noteId, canvasId }` を足す。あれば付箋の作業にする（新しい会話。`threadId` は受けない）
  （作った：画面は `POST /api/claude/note-tasks`（`claude/noteTasks.ts`）を呼び、それが `ClaudeJobs.start` に `note` と材料を渡す）
  - ジョブに `note_id`・`note_canvas_id` の列を足す（ALTER。表の版は上げない）。`origin` は使わない（同時に 2 つまでの数・会話のモデルの取り方が `origin` に頼っているので）
  - 付箋の作業の会話は、会話の一覧（ThreadMenu）に出さない。「チャットで続ける」で開き、会話から 1 つでも頼んだら（付箋でないジョブができたら）一覧に出す
- Claude に送る文：付箋の文、添えた所（ref。今の会話と同じく Claude が `resolve_reference` で読む。付箋の文に書いた ref も、Claude がそのまま読める）、
  付箋の id と Canvas（結果を付箋の近くに置けるように）、続きなら前の付箋の指示と報告、送り直しなら前の作業の記録、近くの付箋（関連する付箋の候補）
- システムプロンプト（付箋の作業のとき）：キャンバスの付箋から頼まれた。最後に、何をしたかを短く報告する（報告は付箋に出る）。
  指示の付箋の文は書き換えない。関連する付箋は、報告の最後の行の `<canvas-related>` に書く（`answer.ts` の `answerFromText` で読む）
- 作業が終わったら（done・failed・cancelled）、サーバーが付箋の `meta.ai.answer` に報告を書く（開いているタブには sync で知らせる。`agent_ops` には残さない。
  タブを閉じていても書ける）。報告には、本文（最後のテキスト）・関連する付箋・モデル・effort・指示の文・時刻・`threadId`・`jobId`・
  変えたもの（キャンバスの編集の batch と label、書いたファイル、Bash のコマンド）・状態を入れる
- 作業の間は、付箋の `meta.ai.task`（`threadId`・`jobId`・始めた時刻）を書いておく（サーバーを再起動して途切れたら、failed にして報告を書く。作った：角の三角の点滅と作業のタブの動作中は、SSE で届く動いているジョブから出す）

### B. サーバー：キャンバスの編集を作業に結び付ける（`mcp.ts`・`agent/ops.ts`・`records.ts`）

- ジョブの Claude Code が canvcode の MCP をつなぐとき、ヘッダーに会話の id を付ける（Agent SDK の `McpHttpServerConfig.headers`。会話ごとにプロセスを立てるので、会話ごとに決まる）
- MCP のハンドラは、ヘッダーの会話の id を `editCanvas` に渡し、`agent_ops` の新しい列 `thread_id` に書く（ALTER）。外の Claude Code からの編集は空のまま
- `POST /api/claude/threads/<id>/undo-canvas`：その会話の編集を、新しいものから順に取り消す。取り消せないもの（そのあと変わった・古くて記録が消えた）があれば、そこで止め、どれを戻したか・どれを戻せなかったかを返す
  （作った：別の API は作らず、`POST /api/claude/note-tasks` の `undo` で戻す。レビューのあと、全部戻せると確かめてから戻すようにした（下の「レビューで見つかったこと」））
- 付箋の報告の「変えたもの」は、この列から集める（ジョブの出来事の label との突き合わせはしない）

### C. 画面：付箋（`useCanvasAnswers.ts`・`AiNoteControls.tsx`・`AnswerView.tsx`・`packages/canvas/src/answers.ts`）

- 送信（➤）でジョブを始める（`/api/claude/answer` は呼ばない）。モデルと effort は今と同じく付箋ごと
- 前の作業がある付箋の送信は、➤ の横に ▾ を出し「前の変更を戻してから送る」を選べる（戻せなかったものがあれば、送らずにそう出す）
- 角の三角：作業の間は点滅、許可を待っている間は警告の色
- 答えのパネル：報告の本文、変えたもの（キャンバスの編集の label。ファイルの名前。Bash のコマンド）、関連する付箋、
  「続けて頼む」「チャットで続ける」「Canvasに残す」。作業の間は、ツールの動き（今の会話の欄と同じ要約）と「止める」
- 「続けて頼む」：元の付箋の下に、前の指示と報告を添えた AI 付箋を置き、矢印を引く（今の「続けて聞く」と同じ置き方）
- 「チャットで続ける」：会話のタブを開き、その付箋の作業の会話を選ぶ
- 前の Q&A の答え（`threadId` のない答え）は、今のパネルで読める（「会話で続ける」も今のまま）

### D. 画面：「作業」のタブ（今の質問のタブ。`QuestionPanel.tsx`）

- 付箋の作業を並べる：動作中（ツールの動きの要約・経過時間・止める）、許可を待っているものは許可のカード（会話のタブの PermissionList と同じ。［断る］が先、全文を出す）、
  過去の作業（報告を持つ付箋。新しいものから）
- 会話の質問は出さない（会話の欄に出す）。ただし、会話の欄に出すのは PR 2 なので、PR 1 では今のまま「作業」のタブに並べる
- Claude のボタンの印・タブの ●N は、付箋の作業の動作中と許可待ちを数える

### E. 画面：チャットの「質問」（`ClaudePanel.tsx`・`ChatLog.tsx`）

- 「質問」で送ったら、会話の欄に、質問と答えをそのまま出す（今の点線のカードの代わり。「質問（Web だけ・会話には入れていない）」の印を付ける）。答えを作っている間は、進み具合と考えている中身と「止める」
- 「会話｜質問」は送っても戻さない
- 答えに「付箋に切り出す」を出す（会話の答えと同じ）

## あとから決めたこと（ユーザーと）

8. 付箋の作業の会話は、会話の一覧に出さない。「チャットで続ける」で開き、会話から 1 つでも頼んだら一覧に出す
9. 質問のタブの名前は「作業」にする（右上のボタンとタブの名前も替える）
10. 会話を選んでいないときにチャットで質問したら、新しい会話を作り、その最初に置く（題は質問の 1 行目）。続けて「会話」で頼むと、同じ会話で Claude Code が動く

## 作っていてわかったこと（PR 1）

- 開発のサーバー（StrictMode）では ClaudeClient が 2 つでき、それぞれが SSE をつなぐ。e2e で SSE を差し替えるときは、つないでいるものすべてに送る
- 付箋の送り方（useCanvasAnswers の ask）が、頼んでいる付箋の一覧（state）に頼ると、送るたびに ask が変わり、それを使う Canvas の画面（CanvasView）が
  作り直されていた（e2e で、送ると付箋の下の欄が消え、キャンバスにフォーカスが移ったことで見つけた）。一覧は ref で読み、ask を変えない
- 付箋の作業の会話が一覧（store.threads）にないと、「チャットで続ける」で開いても読まれなかった。選んだ会話は、一覧になくても読み（loadThread が一覧に足す）、
  消えた会話（404）は覚えて、読み直しを繰り返さない
- MCP の read_canvas は、作業の途中の付箋に ai:working と付け、read_nodes は報告の項目（会話・ジョブ・終わり方・変えたもの）と、作業の途中なら task を返す

## レビューで見つかったこと（PR 1。独立したサブエージェントのレビュー）

1. **（高）サーバーが書いた印と報告が、ブラウザの同期で上書きされていた**。ブラウザは、送っている途中のレコードに届いた変更を捨てる（packages/canvas/src/sync.ts）。
   文字を書いて Ctrl+Enter で送ると、付箋の記録が送られる前（100ms）に作業が始まり、サーバーが書いた `meta.ai.task` を、あとから届いた古い記録が消していた。
   作業の間に付箋を編集したときも、報告が消えた。直し方：
   - SyncHub に見張り（`setGuard`）を足し、ブラウザが送った付箋の記録に、保存してある方の `meta.ai.task` と作業の報告を引き継ぐ（`keepTaskFields`）。
     AI モードをやめた（`meta.ai` のない）付箋は、そのまま受ける。新しく足した付箋（コピーした写し）からは、作業の途中の印を外す
   - 引き継いで変わった記録は、送ったタブに ack のあとで送る（ack の前だと、送っている途中のものとして捨てられる）
   - 印がなくなっていても、ほかの作業の印がなく、報告がその作業より古ければ、報告を書く
2. **（中）記録が古くて消えた編集があっても「戻した」と Claude に伝えていた**。報告の変えたもののうち、まだ戻していないものの記録がなければ、何も戻さずに 409
3. **（中）戻したあとで、同時に動かせる数の上限（429）で始められないと、戻したことが知らされなかった**。戻す前に `ClaudeJobs.assertCanStart` で確かめる
4. **（中）バックグラウンドの作業が報告に書き足すと、作業のファイルとコマンドが消えていた**。会話の付箋のジョブすべての出来事から作る
5. **（低）コピーした付箋で「前の変更を戻す」と、元の付箋の作業を戻していた**。前の作業は、その付箋の会話のときだけ使い（ほかの付箋の会話なら、戻すのは 409、送り直しの記録には使わない）、
   起動したときの回復でも、ほかの付箋の作業の印なら報告を書かない
6. **（低）何枚かの付箋で頼むと、いつも「付箋の文が変わっています」と出た**。`questionIds` を送り、印と報告に移す
7. **（低）「チャットで続ける」のあと、付箋の作業のプロセスが残っていると、会話の依頼が付箋の作業のプロンプトで動いた**。会話から頼んだら、プロセスを閉じて resume で開き直す。
   作業のタブの許可のカードは、付箋の作業しかない会話のものだけにする
8. **（低）バックグラウンドの作業が動いている間、画面は送り直しを止め、サーバーは受けていた**。サーバーも、その付箋のジョブが動いていれば断る
9. **（低）一部だけ戻した状態が残ることがあった**。新しいものから戻していったとして、全部戻せるかを先に確かめる（作った Canvas にあとから足されたものは、戻すときにしかわからない）

## レビューで見つかったこと（PR 2。独立したサブエージェントのレビュー）

高はなかった。次を直した。

1. （中）質問だけの会話で「読み込んでいます…」が消えなかった。読み込んでいない会話で、ジョブも質問もないときだけ出す
2. （中）質問だけの会話の model と effort に、答えたモデル（既定でも Sonnet・medium）が入り、次に会話で頼むジョブがそのモデルで動いた。
   質問だけの会話は model と effort を持たない。会話を作ったときは、入力欄のモデルをそのままにする
3. （低）答えたと届いてから読み直すまで「答えられませんでした」と出た。「答えを読み込んでいます…」にする。答えを作っている間の吹き出しが 1 行目だけだったので、
   start のあとで会話の質問を読み直す
4. （低）作業のタブの ●N に、会話の質問が入っていた。数えない
5. （低）作業のタブの過去の作業（100 件）を、会話の質問が押し出していた。`GET /api/claude/questions` に会話の質問を混ぜない
6. （低）会話の一覧を、質問の時刻を合わせる前に切っていた（最近質問した古い会話が落ちる）。合わせて並べてから切る
7. （低）質問だけの会話は、答えを作っている間 running だった（ジョブのある会話では違う）。running はジョブのことにそろえる
8. （低）前のサーバーで会話を選ばずに聞いた質問が、どこにも出なくなった。起動したときに、それぞれを質問だけの会話にする
9. （低）続けて聞いても、前の質問が渡らなかった。前の答えは、会話の最後に終わったもの（ジョブか質問）にする。質問だけの会話で初めて「会話」で頼むときは、
   最後に答えた質問を取り込んで渡す
10. （低）古いコメントと文言（「答えを見る →」「別枠の質問」）を直した
11. （低）答えを作っている間・答えが届いたときに、会話の欄が下に付いていかなかった。考えている中身と答えの長さもスクロールの合図に入れる
