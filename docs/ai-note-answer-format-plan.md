# AI 付箋の「答えが決めた形になっていません」と、付箋の文に書いた ref を読まないのを直す

AI 付箋で聞くと、「答えられませんでした：答えられませんでした：答えが決めた形になっていません」と出ることがある。
また、付箋の文に貼った `ref:XXXXXXXXXX`（「AIに渡す」でコピーした ID）の中身を、Claude が読めていない。

## わかったこと

ユーザーのワークスペースで失敗した AI 付箋（`node:xOtkhpKcSYKKFcKf`）の文は、次のとおり。付箋の下の欄では、何も添えていない（`meta.ai.contexts` が空）。

```
ref:6GL4xl1yye

それぞれどういう手法なんですか?
```

`ref:6GL4xl1yye` は、PDF（`iberian-2015-explanatory-info-day-ahead-energies`）の 2 ページ目の 1 文（ニューラルネットワークとファジィシステム）を指す。

### 1. 形の失敗

- 付箋で聞くときは、考えている中身を流す（NDJSON）。構造化出力ではモデルが考えないので、`once.ts` は構造化出力を使わず、
  システムプロンプトの最後に「JSON Schema に合う JSON を 1 つだけ返す」と書き足して、返った文字を JSON として読む。
- 同じ質問と近くの付箋を、本物の Claude に送って確かめた（Sonnet・Opus・Haiku、effort を変えて 9 回）。Sonnet・high の 1 回で、同じ失敗が出た。
  そのときの答えは、JSON ではなく、本文の Markdown そのもので、最後に空のコードブロック（```` ```json ```` と ```` ``` ````）が付いていた。
  システムプロンプトの大部分が「Markdown でこう書く」なので、モデルがそちらに引かれ、JSON の頼みを守らないことがある。
- 読めないと、`once.ts` が「答えが決めた形になっていません」の 502 にし、画面は「答えられませんでした：」を前に付けて出す（二重に出るのはこのため）。

### 2. 付箋の文に書いた ref を読まない

- サーバーが読むのは、付箋の下の欄で添えた所（`refs`）だけ。質問の文に書いた `ref:` の ID は、ただの文字として Claude に渡る。
  Claude は Web も MCP も使えない（`once.ts`）ので、中身を見られず、「それぞれ」が何を指すかわからない、と答える。
- 「AIに渡す」で ID をコピーして貼るのは、README が Claude Code に頼むときのやり方として書いている。付箋や会話の「質問」でも同じように使える方がよい。

## 直し方

### A. 考えている中身を流すときは、本文を Markdown のまま返させる（`apps/server/src/claude/answer.ts`）

- 考えている中身を流すとき（`onThinking` を渡し、モデルが adaptive thinking を持つとき）は、`once.ask` に `schema` を渡さない。
  かわりに、システムプロンプトに「答えの返し方」を足す：本文（Markdown）をそのまま書く（JSON にしない、全体をコードブロックで囲まない）。
  関連する付箋は、本文のあとの最後の行に `<canvas-related>node:… node:…</canvas-related>` と書く（なければ空の囲み）。
- 返った文字は `answerFromText` で読む。
  - 最後の `<canvas-related>…</canvas-related>` から `node:…` の id を読み、囲みは本文から外す。囲みがなければ、関連する付箋は空にする（表示だけのもの）。
  - 本文の最後に残った空のコードブロックは外す。
  - モデルが前の頼み方の癖で JSON（`{ "body": …, "related": … }`）を返したら、それを読む（文字が `{` か ```` ```json ```` で始まり、`body` が文字のときだけ）。
- こうすると、モデルが返し方を守らなくても、本文はそのまま答えになる（落ちるのは関連する付箋だけ）。本文が空・長すぎるときは、今までどおり 502。
- 考えている中身を流さないとき（ふつうの JSON で頼むとき）と、adaptive thinking を持たない古いモデルでは、今までどおり構造化出力を使う。
- `once.ts` の「JSON を文字で返させる」仕組みは、ほかに使う所がない。消さずに残し、長い Markdown を JSON に入れさせると形を守らないことがある、と書いておく。

### B. 質問の文に書いた ref も読む（`apps/server/src/claude/answer.ts`）

- 渡す材料（`<canvas-context>`）を、添えた所（`refs`）に加えて、質問の文と前の質問（`previous` の `question`。新しい方から）に書いた `ref:XXXXXXXXXX` からも作る。
  同じ ID は 1 度だけ。合わせて `MAX_REFS`（5）か所まで（添えた所が先）。
- 文に書いた ref の `label` は ID そのものにし、頼む文に「質問の文の中の `ref:…` は、`label` が同じ `<canvas-context>` の中身」と書く（そういう ref があるときだけ）。
- 読めない（消えた・3 日を過ぎた）ときは、添えた所と同じく、そう書いて渡す。
- `POST /api/claude/answer` を使う、会話の入力欄の「質問」でも同じになる。
- 囲みの名前に `canvas-related` を足し、質問などの文の中では開け閉めできないようにする。

## 細分タスク

1. `answer.ts`：`ANSWER_TEXT_FORMAT`・`answerFromText` を足し、考えている中身を流すときは `schema` を渡さずに文字で読む
2. `answer.ts`：`refsOf`（添えた所と、質問・前の質問の文の ref）で材料を作り、頼む文に ref の説明を足す。`ENVELOPE_TAG` に `related` を足す
3. `once.ts`：JSON を文字で返させる仕組みのコメントに、形を守らないことがあると書く
4. テスト（`answer.test.ts`）：Markdown のまま返った答え（囲みあり・なし・空のコードブロック付き・JSON）、考えている中身を流すときに `outputFormat` を渡さないこと、
   文に書いた ref を読むこと（重ねない・上限・添えた所が先・前の質問の ref）、頼む文の説明
5. 本物の Claude で、失敗した付箋と同じ質問を何度か送り、形の失敗が出ないことと、ref の中身を踏まえて答えることを確かめる
6. README（付箋で聞く節）を直す。作業ログ（`docs/2026-11-19.md`）に書く
7. 独立したサブエージェントのレビューを受けて直す。確認用のサーバー（空のワークスペース）を立てて、ユーザーに確かめてもらう

## レビューで見つかったこと（独立したサブエージェントのレビュー）

回帰はなかった。次を直した。

1. JSON として読み直すとき、`once.ts` の `jsonFromText` の救済（最初の `{` から最後の `}` まで）を使っていたので、JSON の例から始まる Markdown の答え
   （```` ```json\n{ "title": …, "body": "…" }\n``` ```` のあとに説明が続くもの）を、例の `body` の値だけに縮めていた。
   外側のコードブロックを除いた全体が JSON として読め、キーが `body`・`related` だけのときだけ JSON として読む（`answerJson`）。
2. 崩れた囲み（`<canvas-related/>`・閉じ忘れ・`` ` `` や ```` ``` ```` で囲んだもの）が本文に残っていた。最後の行の囲みは、崩れた形でも外す
   （本文の最後の本物のコードブロックは消さない）。空のコードブロックを外すのは ```` ```json ```` だけにする（本文の中の、本物の空のブロックを消さない）。
3. 文に書いた ref が上限で落ちても、頼む文が「中身は `<canvas-context>` にある」と言っていた。どの `<canvas-context>` にも `ref` 属性を付け、
   説明を「ref が同じもの」にし、落とした ID は「数を超えたので中身を渡していない」と書く（`refsOf` が `dropped` も返す）。
4. SDK の `result` は、最後の assistant メッセージの最後の text ブロックだけ。出力の上限に達して続きを書かせたときは、後半だけになる。
   最後にツールを呼んだあとの text ブロックをつないで読む（`textCollector`。つないだものが `result` で終わらなければ `result` を使う）。
5. 「答えられませんでした：」が二重に出るのは、形の失敗のほかの誤り（本文がない・長すぎる・ターン数の上限）でも同じだった。
   画面（付箋の通知・答えのパネル・会話の欄）はどれも頭を付けるので、サーバーの付箋の答えの誤りには付けない（`once.ts` の `failure` を空にすると、わけだけにする）。
6. コメントのずれを直した。
