## 全画面のエディタの Claude のパネルが右半分からはみ出す（MAI-102 の不具合）

- 全画面のエディタの右半分に出した Claude のパネルが、会話に長い行があると右半分より広がり、はみ出した右側（送るボタン）が
  切れていた。プランは `docs/claude-panel-editor-overflow-plan.md`。
- 原因：右半分では、パネルの幅を `flex: 1; width: auto` にしていて、flex の子の `min-width` が既定の `auto` のままだった。
  そのため、パネルの最小の幅が、中身の折り返せない一番長い行（ツールの行・コードブロック）の幅になっていた。画面の幅
  1280px（右半分 640px）で測ると、長いツールの行で 1379px、長いコードブロックで 1241px に広がっていた。長い URL は
  折り返すので広がらない。キャンバスの右では `width: 380px` と決まっているので起きない。
- `.file-editor-claude .claude-panel` に `min-width: 0` を足した。長いツールの行は省略記号で切れ、コードブロックは
  ブロックの中で横にスクロールする。
- 回帰の e2e を足した（`tests/e2e/claude-panel.spec.ts`）。直す前は Chromium で落ち（パネルの右端が 3119px）、直したあとは
  Chromium・Firefox・WebKit で通る。
- 狭い画面（画面の幅 722・760・800・900px。右半分は 361〜450px で、キャンバスの右の 380px より狭いこともある）でも、
  見出しと送るボタンの行がパネルの中に収まることを確かめた（直す前は、どの幅でもパネルが 2597px に広がっていた）。
- 型の検査と lint が通った。Claude のパネル・vim のエディタ・触れられる範囲・文字の大きさの e2e を 3 つのブラウザで回し、
  108 件が通り、1 件が落ち、2 件は飛ばした。落ちたのは WebKit の「フォーカスの枠が見た目のボタンに沿う」（デザインパネルの
  「文字」のタブ）で、直す前のコードでも同じように落ちる。
- 4179 のポートはほかの worktree（CanvCode-triangle）の e2e が使っていたので、別のポートで動かす一時的な設定
  （`test-results/tmp.config.ts`。git には入れない）で回した。
- 独立したサブエージェントのレビューを受けた。欠陥はなく、足したテストは直す前に 3 つのブラウザで落ちることも
  確かめてもらった。前からあった見切れを 2 つ指摘されたので、あわせて直した。
  - 置き場所の `.file-editor-claude` の `overflow: hidden` で、右半分が狭いとき（画面の幅 721〜779px）、モデルを選ぶ欄の
    左の端が切れていた（730px で欄の 92% しか見えない）。パネルは `min-width: 0` で収まるので、`overflow: hidden` を外した。
  - `.claude-error` に `overflow-wrap: anywhere` を足した（区切れない長い語で、会話の欄が約 1440px 横にスクロールしていた。
    Chromium・WebKit。Firefox は `/` で折り返す）。
  - e2e に、モデルを選ぶ欄が切れずに見えて押せること（画面の幅 730px）と、長いエラーで会話の欄が横にスクロールしないことを
    足した。どちらも直す前に落ちる。パネルの右端は、右半分の右端と 2px 以内で合うことを確かめるようにした。
- 型の検査と lint が通った。同じ 4 つの e2e を 3 つのブラウザで回し、111 件が通り、2 件は飛ばした。落ちたのは、前からある
