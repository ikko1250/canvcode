# キャンバスの AI（#76・#77）のレビューで見つかった 4 つの不具合を直す

#76（付箋で Claude に聞く）と #77（会話のタブの作り直し）は、レビューを受けずに統合ブランチへ入った。
マージのあと（`05c502f..1828757`）に `/code-review` で見たところ、15 の候補が出た。そのうち次の 4 つを、コードを読んで確かめた
（1 は、使い捨ての e2e で再現した）。ここではこの 4 つだけを直す。

## 1. 三角で開いた答えのパネルから、付箋の下の欄のボタンが押せない

- 付箋の角の三角で答えのパネルを開くと、付箋は選ばない。付箋の下の欄が出ているのは、パネルにフォーカスがあるから
  （`App` の `answerFocused` → `AiNoteControls` の `focusedNoteId`）。
- 欄のボタン（➤・モデルの札・添える所を選ぶ）を押し下げると、フォーカスがボタンへ移る。パネルの `onBlur` が
  `onFocusChange(false)` を呼び、欄が消えるので、クリックが届かない。今の e2e は、欄が見えることしか確かめていなかった。
- 直し方：
  - パネルの `onBlur` は、フォーカスが `.ai-note-controls` へ移ったときは、フォーカスがあるままとする。
  - 欄からほか（パネル以外）へフォーカスが移ったら、欄が `onFocusLeave` で知らせ、`App` が `answerFocused` を落とす。
  - 欄に `tabIndex={-1}` を付ける。Mac の Safari と Firefox は、押したボタンにフォーカスを移さず、フォーカスを持てる一番近い祖先へ移す。
    欄がフォーカスを持てないと、キャンバスへ移って欄が消える。

## 2. 6 か所以上を添えた AI 付箋は、聞くたびに失敗する

- サーバーは、添えた所（refs）を `MAX_REFS = 5` までしか受け付けない（6 個以上は 400）。画面の欄は、いくつでも添えられた。
- 直し方：
  - `@canvcode/canvas` に `MAX_AI_PLACES = 5` を置く（`FOLLOW_UP_TURNS` と同じく、サーバーの上限と同じ値を画面の側に持つ）。
    サーバーのテストで `MAX_AI_PLACES === MAX_REFS` を確かめる。
  - 欄：5 か所添えてあれば、添える所を選ぶアイコンを押しても選ぶ状態にせず、わけを出す（`addContext` でも断る）。
  - 送るとき：前から 6 か所以上添えてある付箋は、送らずにわけを出す（外し方も書く）。

## 3. 編集の途中に「続けて聞く」を押すと、例外で止まる

- `continueAnswer`（答えのパネル）と `continueQuestion`（質問のタブ）は、`editor.begin` の前に
  `editor.store.activeTransaction` を見ていなかった。ほかの 5 か所（Canvasに残す・付箋に切り出す など）は見ている。
- 文字の編集をよそへ預けている・ドラッグの途中などで押すと、`Store.begin` が `Transaction "…" is still open` を投げる。
  `continueAnswer` は、その前にパネルを閉じていた。
- 直し方：ほかの 5 か所と同じく、「編集を終えてから押してください」と出して何もしない（パネルも閉じない）。

## 4. 会話の質問が「動いている」のまま残ることがある

- 会話の質問は、答えを claude.db に書いてから一覧から外す。`finishQuestion` が投げると（claude.db がふさがっている・書けない）、
  catch に入り、そこでもう一度 `finishQuestion` を呼んで投げ、`questions.end` まで届かない。
  動いている質問の一覧に残り、すべてのタブで点滅し続け、「止める」も効かない（サーバーを再起動するまで）。
- 直し方：catch の中の `finishQuestion` は、投げても記録だけして、`questions.end` を必ず呼ぶ。
