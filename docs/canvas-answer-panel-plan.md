# 付箋で聞き、答えは付箋の横のパネルで見る（キャンバスの AI の作り直し）

Canvas「授業_2026秋」に置いた付箋とモック（ref:bbHUgjgSaC・ref:EAZ6bA97ad。ref は 3 日で消える）をもとにした計画。
このブランチ（`koukunpadi1250/canvas-ai-buttons`）の 3102619 で作った「付箋で聞き、付箋で答える」を作り直し、
右のパネルを「会話｜質問」のタブにする。3102619 と f970e6b は、まだ main に入っていない。

## 目的（付箋に書いてあったこと）

- 付箋を入力にするのはよかった。答えを付箋（段落ごとの付箋とボタンのフレーム）で出すのは、よくなかった
- 付箋を入力にすると、会話を途中からやり直せる。チャットでは会話の全体が 1 本につながるので、作業を頼んでいる途中に、自分の理解のための質問を混ぜると、作業の文脈が散らかる。作業の指示と質問は分けたいが、チャットは分けるように作られていない
- そこで、答えはキャンバスに置かず、付箋の角の三角から開くパネルで見る。残したいものだけを「Canvasに残す」で置く
- 聞いた質問は、右のパネルの「質問」のタブに、どの Canvas からでも一覧で出す。会話（チャット）と質問は、同じパネルのタブで行き来する

## 決まったこと（2026-11-18）

- 答えのパネルは、付箋の右に出す
- 「Canvasに残す」は、書式付きのテキスト 1 つにする
- 答えのフレームとボタンの型は消す
- 関連する付箋の候補は、質問の付箋に近い 30 枚
- 右のパネルは、モック（質問パネルの案・チャットのパネルの案）のとおり「会話｜質問」のタブにする。2 段に分けて作る（下の「段階」）
- 動いている質問は、サーバーが持ち、すべてのタブ・端末に流す（ほかのタブで頼んだものも、一覧に出て、三角が点滅し、止められる）
- まだ見ていない印（青い点）は、ブラウザごとに覚える
- 右上のボタンは「Claude」から「質問」に替える
- 段階 B の入力欄の「質問」では、会話の最後の答えを添える

## 今の作り（3102619）

- 答えは、質問の付箋の下に置くフレーム。中に前提の付箋・段落ごとの付箋・書き直すボタン（新しいノードの型 `button`）・左右の「＋」・版の帯（`packages/canvas/src/answers.ts`）
- AI 付箋（`meta.ai`）の下に、モデル・「＋ 選んでいる所」・送信の欄をいつも出す（`apps/web/src/claude/AiNoteControls.tsx`）
- 待っている間は、付箋の右に HTML の「Claude が答えを書いています」と × を出す（`App.tsx` の `answering.map`）
- 右上の「Claude」と C で、付箋の答えのパネル（`AnswerPanel`）を開き、「チャット →」でチャット（`ClaudePanel`）に移る。答えの記録（`AnswerLog`）は localStorage
- サーバーは `POST /api/claude/answer`。返すのは `{ title, assumptions, paragraphs, hints }`

## 段階

- **段階 A（このブランチ）**：付箋で聞いて三角とパネルで見る。右のパネルを「会話｜質問」のタブにし、質問のタブ（一覧・答え・この場で続けて聞く）を作る。会話のタブの中身は今のチャットのまま。フレームとボタンの型を消す
- **段階 B（次のブランチ）**：会話のタブを、チャットのパネルの案のとおりに作り直す。会話と付箋の行き来（付箋に切り出す・会話で続ける）と、入力欄の「会話｜質問」を足す

1〜11 は段階 A。段階 B は最後の節。

## 全体の形（段階 A）

1. 付箋に書いて送る（送信か Ctrl+Enter。右クリックの「Claude に聞く」でもよい）
2. 付箋の角に三角が出て、点滅する。質問のタブの「動作中」にも出る。ほかのタブ・端末でも同じ（サーバーが流す）
3. 答えが届いたら、付箋の `meta.ai.answer` に書く（Undo 1 回で消える）。三角の点滅が止まる。質問のタブの「過去の回答」に青い点付きで出る
4. 三角を押すと、付箋の右にパネルが開く。本文・関連する付箋・「続けて聞く」「Canvasに残す」
5. 「続けて聞く」は、付箋の下に続きの AI 付箋を置き、矢印を引いて文字の編集を始める。付箋の上に前の答えの札が出る。送ると、前の質問と答えを踏まえて答える
6. 「Canvasに残す」は、答えを 1 つのテキストにして、付箋の右に置き、付箋から矢印を引く
7. 質問のタブからは、ほかの Canvas の答えも読める。「続けて聞く」「Canvasに残す」は、いま開いている Canvas に置く

答えの本文は付箋に持たせる。キャンバスのレコードなので、同期し、Undo に乗り、ワークスペースのバックアップにも入る（`claude.db` はバックアップに入らず、開けなければ作り直すものなので、答えの置き場所にしない）。

## 1. 答えを付箋に持たせる（`packages/canvas/src/answers.ts`）

`meta.ai` を次の形にする。

```ts
interface AiNoteMeta {
  contexts: AiContext[]
  model?: string
  effort?: string
  // 届いた答え（新しいもの 1 つ。送り直したら置き換える。前の答えは Undo で戻す）
  answer?: AiAnswer
}

interface AiAnswer {
  // 本文（Markdown）
  body: string
  // 関連する付箋の id（同じ Canvas。消えたものはパネルに出さない）
  related: string[]
  // 答えたモデルと effort（パネルの札に出す）
  model: string
  effort?: string
  // 送ったときの質問の文字（付箋の文字と違えば、パネルに「質問が変わっています」と出す。続きを聞くときに前の質問として渡す）
  question: string
  // 付箋を何枚か選んで聞いたときの、ほかの付箋（答えは読む順で最初の付箋に持たせる）
  questionIds?: string[]
  answeredAt: number
}

// 前の質問と答え（続きを聞くときに Claude に渡す。古い方から）
interface PreviousTurn {
  question: string
  answer: string
}

type AiContext =
  // 前の答え（続き）。turns は「続けて聞く」を押したときの写し（古い方から 3 つまで、12000 文字まで。最後が元の付箋の質問と答え）。
  // 元の付箋がほかの Canvas にあっても（読み込んでいなくても）、元の付箋が消えても、送れるように写しを持つ
  | { kind: 'answer'; noteId: string; canvasId: string; label: string; turns: PreviousTurn[] }
  // 選んだ所（今のまま）
  | { kind: 'canvas'; label: string; target: CanvasRefTarget }
```

- 足す関数
  - `setAiAnswer(editor, noteId, answer, label)`：`meta.ai` を残して `answer` だけを書く（AI モードでなければ AI モードにする）
  - `followUpContext(noteId, canvasId, meta)`：元の付箋の `meta.ai` から続きの札を作る。`turns` は、元の付箋の前の答えの札の `turns` に、元の付箋の質問と答えを足し、3 つ・12000 文字に収まるまで古いものから落とす
  - `placeFollowUpNote(editor, tx, noteId, context)`：元の付箋の下（重なれば空いている所）に AI 付箋を置き、`contexts` に続きの札を入れ、矢印を引く。幅は元の付箋にそろえる
  - `placeFollowUpAt(editor, tx, point, context)`：元の付箋がこの Canvas にないとき。画面の真ん中に置く（矢印は引かない）
  - `placeAnswerText(editor, body, at)`：`richTextFromMarkdown` で本文をテキストにして置く。`at` が付箋なら、その右（重なれば空いている所）に置いて矢印を引き、点なら、そこに置く。Undo 1 回
  - `answerCandidates(editor, questionIds)`：関連する付箋の候補。この Canvas の文字のある付箋（入れ子の中も。質問の付箋は除く）を、質問の付箋との隙間が小さいものから 30 枚、1 枚 200 文字まで
- 送って答えを置いても、AI モードは解かない（答えを持つので）
- 付箋の Markdown（`richMarkdown.ts`）は見出し・太字・箇条書き・``` を読めるので、「Canvasに残す」で書式が残る。表は文字のまま残る

## 2. サーバー

### 2.1 答える（`apps/server/src/claude/answer.ts`）

- 返す形を `{ body, related, model }` にする。`title`・`assumptions`・`hints` はやめる
  - 前提は、決めたときだけ本文の最初に短く書かせる
  - 本文は付箋の Markdown でも読める書き方にさせる（段落の間に空の行、見出しは `###` まで、表は使わない）
- 頼む形：`{ question, previous?: { question, answer }[], refs?, candidates?: { id, text }[], source?: { noteId, canvasId, label }, model?, effort? }`
  - `current`・`instruction`（書き直し）はやめる
  - `source` は、どの付箋の質問か（下の 2.3 の、動いている質問の一覧に使う。`label` は質問の 1 行目）
  - NDJSON の最初の行で、動いている質問の id を返す：`{ type: 'start', id }`
  - `candidates` は、関連する付箋を選ばせる候補。画面が、同じ Canvas の付箋（質問の付箋は除く）を、質問の付箋に近いものから 30 枚まで、1 枚 200 文字までにして送る
  - 候補は材料として `<canvas-candidate id="…">` で囲んで渡す（質問と同じく、中の文で囲みを開け閉めできないようにする）
  - `related` は 3 つまで。候補にない id は落とす（表示だけのものなので、黙って落としてよい）
- 進み具合を NDJSON で流す：`{ type: 'step', step: 'read' | 'search' | 'write' }`
  - 始めたら `read`。WebSearch・WebFetch を呼んだら `search`。答えの文字が来始めたら `write`（`once.ts` が流すメッセージから決める）
  - 調べなかったときは `search` が来ない（一覧では「調べる」を薄く出す）
- 長さの上限：本文は `MAX_ANSWER_LENGTH`（12000 文字）のまま。超えたら 502
- 考えている中身の NDJSON・Web を調べること・`MAX_RUNNING_ANSWERS` は今のまま

### 2.2 質問の一覧（`apps/server/src/claude/questions.ts`、新しく作る）

画面は開いた Canvas の分だけレコードを読む（`docs/lazy-canvas-loading-plan.md`）ので、ほかの Canvas の答えはサーバーから読む。

- `GET /api/claude/questions?canvasId=…`：答えを持つ付箋の一覧（新しいものから 100 件まで）。`canvasId` を省けば、すべての Canvas
  - 1 件は `{ noteId, canvasId, canvasTitle, question（1 行目、60 文字まで）, model, effort, answeredAt }`
  - `workspace.db` の付箋のうち `json_extract(body, '$.meta.ai.answer') IS NOT NULL` のものを読む（`records.ts` に `quoteCards()` と同じ形の `answeredNotes()` を足す）。ゴミ箱の中の Canvas のものは出さない
- `GET /api/claude/questions/<noteId>`：その付箋の `meta.ai`（答えと札）と、Canvas の id・題
- 動いている質問は、この一覧に入れない（下の 2.3）

### 2.3 動いている質問（`apps/server/src/claude/questions.ts`）

動いている質問は、サーバーがメモリに持ち、Claude のパネルの SSE（`GET /api/claude/events`。`claude/http.ts`）で、すべてのタブに流す。
答えを付箋に書くのは、今までどおり頼んだ画面（文字の編集の最中に書かないように、`settle` で待ってから書くため）。

- 1 件は `{ id, noteId, canvasId, label, model, effort, status: 'running' | 'placing', step, thinking, startedAt }`
  - `placing` は、答えを画面に渡し、画面が付箋に書くのを待っている間
  - `thinking` は 20000 文字まで（今の `KEPT_THINKING` と同じ）
- SSE に足すもの
  - つないだときの `snapshot` に `questions`（動いているものすべて）
  - `{ type: 'question', question }`：始まった・進み具合が変わった・`placing` になった
  - `{ type: 'question-thinking', id, text }`：考えている中身の続き（今の `THINKING_FLUSH_MS` ごとにまとめる）
  - `{ type: 'question-done', id, status: 'done' | 'failed' | 'cancelled' }`：終わった。受けたタブは、過去の回答を読み直す
- `POST /api/claude/questions/<id>/cancel`：止める（どのタブからでも）。Claude を止め、頼んだ画面の NDJSON は「やめました」で終わる
- `POST /api/claude/questions/<id>/finish { status, error? }`：頼んだ画面が、付箋に書いた（書けなかった）ことを知らせる。`placing` のものを終わりにする
  - 知らせが来ないまま `PLACING_TIMEOUT_MS`（10 分）たったら、終わりにする（頼んだ画面を閉じたなど）。そのときは `done` として流す（ほかのタブは読み直して、書けていれば出る）
- 頼んだ画面が答えを受け取る前に NDJSON を切ったら（タブを閉じた・やめた）、今と同じく Claude を止め、`cancelled` として流す
- SSE は、Claude を使えるとわかったらすぐつないでいる（`claudeClient.ts` の `check()`。許可を待つ問い合わせの印のため）ので、そのまま使える
- 頼んだ画面は、答えを付箋に書くのを待っている間に、ほかのタブで止められた（SSE の `question-done` が `cancelled`）と知ったら、書くのをやめる（`claudeClient.ts` の `finishedQuestions`）

## 3. 角の三角（`packages/canvas`）

三角は付箋の中身ではなく、ハンドルと同じ画面の部品として扱う。オーバーレイの層に描き、書き出し・サムネイル・`render_canvas` には入れない。

- 出す付箋：`meta.ai.answer` がある付箋と、答えを作っている付箋
- 大きさ：ワールドで 22（モックの付箋 220 に 21.6）。付箋が小さければ `min(w, h) / 3` まで縮める
- 当たり判定：右上の角から `max(三角の大きさ, 24 / zoom)` の四角。ただし付箋の `min(w, h) / 2` を超えない（縮小しても付箋そのものは選べるように）
- ホバー：1.25 倍で描き、カーソルを指にする
- 点滅：答えを作っている間、不透明度を 0.35〜1 の間で 1.2 秒ごとに行き来させる。`view.ts` の `frameCallbacks` で、作っている付箋がある間だけオーバーレイを描き直す
- 付箋が画面で 16px（`AI_CORNER_MIN_NOTE_PX`）より小さく見えるときは描かず、当たりもない
- 新しいファイル `aiCorner.ts`：三角の箱・当たり箱の計算と、オーバーレイに描く関数
- `session.ts` に足す
  - `answeringIds: ReadonlySet<string>`：答えを作っている付箋（画面が、サーバーの動いている質問のうち、この Canvas のものから立てる。ほかのタブで頼んだものも点滅する）
  - `hoveredAiCorner: string | null`
- `tools.ts` の `SelectTool`：間隔のハンドルの次、ノードより先に三角を調べる（`hitSpacingHandle` と同じ並び）。押して離したら `ToolContext.openAnswer(noteId)` を呼ぶ。動かしたらふつうのドラッグにはしない（何もしない）
- 固定した付箋・グループの中の付箋でも押せる（選ぶことはしないので）

## 4. 答えの中身（`AnswerView.tsx`）と付箋の横のパネル（`AnswerPopover.tsx`）

答えの中身は、付箋の横のパネルと、質問のタブの答え（下の 6 の ②）で同じものを使う（`apps/web/src/claude/AnswerView.tsx`）。

- 本文：チャットと同じ `renderMarkdownToSafeHtml`
- 質問の付箋の文字が、送ったときと違えば、本文の上に「質問が変わっています（送り直すと答え直します）」
- 関連する付箋：↗ と 1 行目（30 文字まで）。押すと、その付箋へ移って選ぶ（ほかの Canvas なら、その Canvas に移ってから）
- 下：「続けて聞く」「Canvasに残す」（全画面のエディタでは出さない。付箋を置けないので）
- 答えを作っている間：本文の代わりに、進み具合と考えている中身（サーバーが流すもの。今の `AnswerThinking` を使う）と「やめる」（ほかのタブで頼んだものも止められる）
- 失敗したとき：前の答えがあればそれを出し、上に失敗のわけを 1 行出す

付箋の横のパネル（`AnswerPopover.tsx`、新しく作る）：

## 気をつけること

- 答えを付箋に書くのは頼んだ画面なので、答えができる前に頼んだタブを閉じると、ほかのタブで見ていても止まる（今と同じ）。答えができたあと、付箋に書く前に閉じたときは、答えは残らない（`placing` は 10 分で一覧から消える）
- まだ見ていない印はブラウザごとなので、別の端末では、見た答えにも青い点が付く
- 動いている質問はサーバーのメモリにだけあるので、サーバーを再起動すると、動作中の一覧から消える（Claude も止まる）
