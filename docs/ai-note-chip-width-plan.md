# AI 付箋の上の札を、付箋の幅より広くしない

ユーザーの頼み：AI 付箋で続けて聞いたときに付箋の上に出る UI（札）が、キャンバスを縮小していくと付箋の横幅より大きくなる。邪魔になるのでやめる。

## 今の作り

- 札（`AiNoteControls.tsx` の `.ai-note-chips`）は、前の答えを添えた付箋（「📎「質問」の答え」と「↗ 元の付箋」）と、
  会話の答えを添えた付箋（「💬 会話「題」の答え」と「↗ 会話へ」）の上に出す。
- 幅は `Math.max(220, 付箋の画面の幅)`。付箋の既定の幅は 220 なので、ズーム 1 では付箋と同じ幅だが、縮小すると付箋より広くなる
  （ズーム 0.3 で付箋は 66px、札は 220px のまま）。
- 札の名前は残りの幅に縮めて省略記号を付けるが、↗ のボタンは縮まない（`flex: none`）。Canvas の名前が長いと、ボタンだけで札の幅を超える。

## 直し方

1. 札の幅を、付箋の画面の幅にする（下限をなくす）。付箋の下の欄（添えるもの・モデル・送信）は、押すものが多いので 220px の下限のままにする。
2. 札の中の詰め方（`styles.css`）：
   - 名前は今のまま、残りの幅に縮めて省略記号を付ける。
   - ↗ のボタンは、札の中身の幅の半分までにし、はみ出す分は文字に省略記号を付ける（中の span で切る。ボタンで切ると、ボタンの当たりも切れる）。
3. 札が 180px より狭いときは、ボタンを「↗」だけにする（名前に幅を回す）。読み上げの名前は `aria-label` で今のまま（「↗ 元の付箋」など）。
4. 札が 56px より狭いとき（「↗」と名前の頭も入らない）は、札を出さない。既定の幅の付箋なら、札を出す最小のズーム（0.3）でも 66px あるので出る。
5. 書式のツールバー（`TextFormatToolbar.tsx`）は、AI 付箋の右に出すとき「札と欄の右」に出している。札は付箋より広くならないので、欄の右とする
   （欄の幅の下限は 220px のままなので、計算は変えない。コメントだけ直す）。

## 確かめること

- e2e：続きの付箋を縮小していき（ズーム 1・0.5・0.3）、札の幅が付箋の画面の幅と同じで、中身が札からはみ出さないこと。
  狭いときはボタンが「↗」だけで、名前は「↗ 元の付箋」のまま。付箋を狭くして 56px を下回ったら札を出さないこと。
- 既存の e2e（canvas-answer・claude-panel・target-size・ui-typography）が通ること。

## レビューで見つかったこと

独立したサブエージェントのレビューで、はみ出し・ボタンの当たり・読み上げの名前に問題はなかった。次を直した。

- e2e が、ボタンを札の中身の半分で切る所を通っていなかった（`max-width: 50%` を消しても通った）。ほかの Canvas の長い名前の札を足し、
  ボタンが半分までで文字を切っていることを見る。はみ出しは、札の外の枠ではなく内側（余白と枠を除いた所）と比べる。会話の札（↗ 会話へ）も見る。
- 狭い札ではボタンが「↗」だけになり、移る先の Canvas の名前が見えない。ほかの Canvas なら、ボタンの説明（title）にその名前を入れる。
- e2e の古いコメント（「札と欄（付箋より広い）」）を直した。
- 直さないこと：付箋そのものが狭い（画面で 56px より狭い）と、札を出さない。札は付箋より広くしないという頼みからそうなる
  （ズームすれば出る）。選んでいる付箋だけ「↗」の札を出す案もあったが、それは付箋より広くなるのでしない。
