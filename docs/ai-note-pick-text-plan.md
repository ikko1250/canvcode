# AI 付箋の添える所を、PDF の文字をなぞって選ぶ

AI 付箋の「添える所を選ぶ」は、今は範囲（矩形）をドラッグするか、ノードをクリックするかしかない。
2 段組の論文で「左の段の途中から右の段の頭まで」を選ぶと、矩形では隣の段や図のキャプションまで入る。
そこで、添える所を選んでいる間は、PDF のページの上の Ctrl（⌘）+ドラッグで、文字を読む順になぞって添えられるようにする
（操作 `o` の「文字を選ぶ」（MAI-103）と同じ動き）。

ブランチ：`koukunpadi1250/ai-note-pick-text`（`koukunpadi1250/mai-37-41-integration` から）。

## 1. Ctrl（⌘）+ドラッグで、PDF の文字をなぞって添える

- Ctrl（⌘）+ドラッグは、今は「ノードの上からでも範囲選択にする」（`tools.ts` の `onPointerDown`）。
  PDF のページは固定したノード（`locked`）なので、ふつうのドラッグでもう範囲選択になる。ページの上の Ctrl（⌘）+ドラッグは
  ふつうのドラッグと同じ動きで、なぞりに替えても失うものがない。替えるのは、添える所を選んでいる間だけにする。
- セッションに `pickingContext`（添える所を選んでいる間）を足す。`AiNoteControls` が選ぶ状態の間だけ true にする。
- 選択のツール：`pickingContext` のときの、PDF のページの上の Ctrl（⌘）+押し下げを、語をなぞる状態（`selectingWords`）にする。
  なぞっている間は「文字を選ぶ」と同じくハイライトし、カーソルは文字を選ぶ形にする。
  動かさずに離した（クリック）なら、何も添えない（1 語だけを添えても役に立たないので）。
- View：離したら、選んだ文字を PDF の範囲の参照（`PdfRefTarget`：ファイル・ページ・範囲・文字。改行は入れない）にして、
  `onTextPick` で見張っている所（`AiNoteControls`）に渡す。範囲は「文字を選ぶ」と同じく、選び始めた段の部分を囲む。
  文字を読めないページ（スキャンした PDF など）なら、今と同じくそう知らせる（範囲で囲めば、図として添えられる）。
- 添えるもの（`AiContext` の `canvas`）は、今は `CanvasRefTarget` しか持てない。`PdfRefTarget` も持てるようにする。
  送るときに ref にするのは今と同じ（`saveReference` は PDF の範囲の ref も受ける）。サーバーは ref の中身の
  `content.text` に選んだ文字、`pageText` にそのページの文字を返すので、変えなくてよい。
  MCP の `read_nodes` は、今と同じく `{ kind: 'canvas', label }` を返す。
- 名前は「PDF の 3 ページ「冒頭 16 文字…」」（「Claude に頼む…」の名前と同じ書き方）。
  同じ所（ファイル・ページ・文字・範囲が同じ）は 2 回添えない。

## 2. Ctrl（⌘）を押している間は、続けて添えられる

- 今は 1 か所添えると、選ぶ状態を抜けて付箋を選び直す。何か所もなぞるには、毎回アイコンを押すことになる。
- 添えたときに Ctrl（⌘）を押していれば、選ぶ状態のままにする（なぞり・範囲・ノードのクリックのどれでも）。
  そのあと Ctrl（⌘）を離すと、選ぶ状態を抜けて付箋を選び直す。何も添えずに離したなら、抜けない（ズームのために押したなど）。
  ウィンドウからフォーカスが外れたとき（⌘+Tab など。離したことが届かない）も、離したとみなす。
- 押しているかは、キーと、ポインタのイベントの修飾キーで決める（選ぶ状態に入る前から押していても分かるように）。
- 5 か所に達したら、選ぶ状態を抜ける。
- 修飾キーなしで添えたときは、今と同じく 1 か所で抜ける。

## 3. 範囲で PDF のページを囲んだときに、その文字を添える（見つかった不具合）

- 範囲で PDF のページを囲んで添えると、ref のノードにはページの番号とファイルの場所しか入らない。
  「AIに渡すIDをコピー」は、枠がかかった範囲の文字を読んでノードに付けている（`pdfRegionRequests`・`withPdfRegions`）が、
  AI 付箋の送信（`saveReference(place.target)`）は付けていない。付箋で答える Claude は Web しか使えず、ファイルを読めないので、
  PDF の文字は何も届いていなかった。
- 添えるときに、枠がかかったページの範囲の文字を読んでノードに付ける（ref が 3 日で消えても文字は付箋に残る）。
  付箋で答える Claude はファイルを読めないので、ページのほぼ全体を囲んだときも、ページ全体の文字を付ける
  （「AIに渡すIDをコピー」は今のまま。会話の Claude は `textPath` を読める）。ページは 8 枚まで（今の上限と同じ）。

## 4. 見せ方

- 選んでいる間の札：「範囲をドラッグか、ノードをクリック」の後ろに「（⌘ で文字）」（Mac 以外は Ctrl）。
- アイコンの説明（title）に、なぞり方と、押している間は続けて添えられることを書く。
- 選ぶ状態を抜けたら、なぞったハイライトを消す。

## 5. しないこと（あとの段）

- Markdown カードのなぞり：カードは絵（タイル）で描いているので、文字の位置が分からない。ブロック（段落・見出し・箇条書きの
  1 項目）単位なら、`renderMarkdown` の `data-line` から行の範囲（`LinesRefTarget`）にできそう。確かめてから別にする。
- Portal 越しの PDF：なぞれるのは、今の Canvas の上の PDF のページだけ（今の範囲選択と同じ）。

## 6. テスト

- 単体：`pdfRegionRequests` のページ全体を含める指定、`AiContext` の PDF の範囲の読み込み（`contextOf`）・同じ所の判定・名前。
- e2e（`tests/e2e/ai-note-pick-text.spec.ts`。PDF のページと AI 付箋を置いた Canvas）：
  - 選ぶ状態で Ctrl+ドラッグでなぞると、選んだ文字を添える。押したまま 2 か所目もなぞれ、離すと付箋を選び直す。
  - 動かさずに Ctrl+クリックしただけでは添えない。
  - 送ると、PDF の範囲の ref（選んだ文字）を保存して、その refId を送る。
  - 修飾キーなしで範囲で囲むと、1 か所で抜け、ref のノードに範囲の文字が付く。
