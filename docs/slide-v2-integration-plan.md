# slide-v2 の CanvCode 統合計画

## 目的

CanvCode のワークスペース上でスライドデッキを作成・取り込み・編集し、プレビューと PDF / PNG 出力まで行えるようにする。slide-v2 のデッキ形式とレイアウトを保ち、CanvCode のファイル同期、キャンバス階層、カードの所有・削除の仕組みに接続する。

調査した slide-v2 は `main` の `fa1fa69`（package version `2.0.0`）。主な再利用対象は `src/core/` のスキーマ・レイアウト・Markdown 入出力・lint、`src/browser/renderer.ts` と `styles/slide.css`、およびエディタの状態管理・履歴である。

## 推奨する形

- デッキを CanvCode の File として保存し、キャンバスには専用カードを置く。カードには表紙スライドの縮小プレビューを表示し、開くと編集画面へ進む。
- デッキファイルには `.slide.md` または `.slide.json` を使い、通常の Markdown ファイルと区別する。slide-v2 の Markdown / JSON 内容はそのまま保持できる。
- レイアウト計算、型、検証、Markdown パーサー／ライター、容量 lint、描画 CSS を `packages/slides` にまとめる。ブラウザで使いやすいよう、DOM 要素へ直接描画する既存 renderer は再利用可能な関数に整理する。
- CanvCode の画面は React に統一し、slide-v2 の編集操作と画面構成を移植する。これにより別サーバーや二重のフロントエンド起動を持ち込まない。
- スライド画像はデッキからの相対パスを維持する。サーバー側でワークスペース内にパスを制限し、画像形式とサイズを検証する。インポート時はデッキと相対画像を一緒にコピーする。
- PDF / PNG は CanvCode の既存サーバーから出力する。PDF は単一ファイル、複数 PNG は ZIP にまとめてダウンロードできる形にする。

## 対象にする機能

- 表紙、箇条書き、全幅の表、表＋画像／コード、表＋2画像の5レイアウト
- スライドの追加、複製、削除、並べ替え
- フォーム編集と Markdown / JSON ソース編集
- プレビュー、入力検証、容量 lint の警告、undo / redo
- 相対画像の選択・追加
- PDF と PNG の出力
- 既存 slide-v2 の `.md` / `.json` デッキの取り込み

## 実装フェーズ

### 1. 共通スライドエンジンを切り出す

- slide-v2 の `src/core/` を `packages/slides/src/` に移し、CanvCode の package workspace から利用できるようにする。
- `styles/slide.css` とブラウザ renderer を追加し、エディタのプレビューとサーバーの出力で同じ描画経路を使う。
- Markdown / JSON の読み書き、既存5レイアウト、行数計算、容量 lint の挙動を維持する。

### 2. ワークスペースの File とカードに接続する

- `FileRecord` とサーバーの FileStore に `slides` 種別を追加する。`.slide.md` / `.slide.json` の作成・一覧・読込・保存・名前変更・外部変更監視を扱う。
- CanvCode の既存のハッシュ照合による競合検出と自動保存を使う。
- `slide-deck-card` ノードを作り、通常の File カードと同じ所有・ショートカット・ゴミ箱の扱いにする。
- パイメニューまたはキャンバス上の作成操作から新規デッキを作れるようにする。カードのダブルクリックで編集画面を開く。

### 3. 編集画面を CanvCode に統合する

- `apps/web/src/slides/` に React の全画面編集画面を作る。
- slide-v2 のスライド一覧、フォーム／ソース切替、プレビュー、問題一覧、undo / redo を移植する。
- 編集中のデッキを既存 File API 経由で保存し、CanvCode の外でファイルが変わった場合は既存の競合 UI へつなぐ。
- アプリの戻る操作で元のキャンバスへ戻れるようにする。

### 4. 画像と PDF / PNG 出力を統合する

- サーバーにデッキ読込・画像解決・検証・出力の処理を追加する。相対パスをワークスペース外へ解決できないように制限する。
- slide-v2 の Playwright 出力処理を再利用し、出力をユーザーがダウンロードできる API にする。
- Chromium を実行時依存として扱い、セットアップ手順を README に追加する。
- slide-v2 は Google Fonts から M PLUS 1p を取得する。VPS やオフラインでも表示が揃うよう、フォントの再配布条件を確認してローカル配信に切り替える。

### 5. 既存デッキを取り込む

- `.md` / `.json` と相対画像を CanvCode のワークスペースへコピーし、`.slide.md` / `.slide.json` の File として登録する。
- 画像が見つからない、またはデッキ形式が不正な場合は、取り込み前に該当ファイルと理由を表示する。
- 取り込んだデッキは通常のキャンバスカードから開けるようにする。

## 完了条件

- 新規デッキと既存デッキを CanvCode 上で開ける。
- 5レイアウトすべてをフォーム／ソースの両方から編集でき、プレビューと警告が更新される。
- 保存後のデッキが Markdown または JSON としてワークスペースに残り、CanvCode 外での変更も既存の競合処理に反映される。
- PDF を1ファイル、PNG を ZIP としてブラウザから取得できる。
- スライドカードは他の File カードと同様にキャンバス階層・複製・削除・復元に従う。
- 通常の Markdown ファイルは、スライドデッキとして誤認されない。

## 主な注意点

- CanvCode のファイル種別・FileRecord・カード参照を拡張するため、保存済みワークスペースの既存レコードとの互換性を保つ。
- PDF / PNG 出力には Chromium が必要になる。VPS でのインストール方法と実行時依存を導入時に明記する。
- 現在の slide-v2 renderer は専用 HTML ページを前提にする。共通化では寸法・CSS・フォント読込を変えず、エディタ表示と出力の見た目を揃える。
- 画像アップロードと相対パス解決はワークスペース内に限定する。

## 初期対象外

- PowerPoint（PPTX）の入出力
- 任意のアニメーション、動画、独自レイアウトの追加
- CanvCode の複数タブ同時編集を前提にした共同編集
