# CanvCode

ドキュメント管理機能と階層構造を持つ infinite canvas。設計は Linear の MAI-1（MAI-2〜MAI-16）を参照。

現在は段階 11-2（旧データの取り込み）まで。MAI-2 の導入順はここで一巡した。ほかに、Markdown カードを画像にして描く方法の検証ページ（`?lab=markdown`）がある。キャンバスとノードはサーバーの SQLite に保存され、同じワークスペースを開いたほかのタブ・端末にもすぐ届く。

## 構成

| パス | 内容 |
| -- | -- |
| `packages/core` | 幾何計算・カメラ・fractional index・ID・ストア・Undo（DOM に依存しない） |
| `packages/nodes` | ノードの型（`defineNodeType`、図形・テキスト・付箋・画像・フリーハンド・矢印・Portal・グループ・フレーム・Markdown カード・コードカード・スライドデッキ・PDF のページ） |
| `packages/canvas` | ワークスペース（ストア・履歴・階層・ゴミ箱）・Canvas ごとの Editor・描画（Canvas2D の 3 レイヤー）・入力・ツール・空間インデックス・矢印のつながり・File の読み書きと編集（CodeMirror） |
| `packages/slides` | スライドの Markdown／JSON パーサー、レイアウト・lint・ブラウザ描画・編集履歴 |
| `apps/web` | React の画面（サイドバー・パンくずリスト・右クリックメニュー・全画面のエディタ）と Preact 製スライドエディタ |
| `apps/server` | Node のサーバー（127.0.0.1 でのみ待ち受け、ビルドした画面の配信、レコードの保存（SQLite）と WebSocket での同期、画像・PDF・スライド出力・サムネイルの保存、ファイルの読み書きと変更の監視） |

## 使い方

Node 24 以上が必要。

```bash
npm install
npx playwright install chromium  # PDF / PNG 出力用（初回のみ）
npm run build   # 型チェックと画面のビルド
npm start       # http://127.0.0.1:8787
```

ワークスペースのフォルダは `npm start -- --workspace <フォルダ>` か、環境変数 `CANVCODE_WORKSPACE` で指定する（既定は `./workspace`）。

- Markdown と Python は、ワークスペースのフォルダに普通の `.md` / `.py` ファイルとして置く（サブフォルダも可）。SSH から Neovim などで直接編集してよく、変更はブラウザに届く
- スライドデッキは `.slide.md` または `.slide.json` として保存される。キャンバスのパイメニュー `a` → `Portal` → `スライド` から新規作成できる。既存の `.md`／`.json` デッキはスライドエディタの「読み込み」で取り込める。画像も一緒に選ぶと、参照画像はワークスペースの `assets/` に保存してデッキの相対パスを合わせる。取り込んだデッキはサイドバーの「未配置」からキャンバスへ置く
- スライドエディタではフォーム／Markdown・JSON ソースの編集、プレビュー、undo/redo、PDF と PNG ZIP の出力ができる。画像付きデッキの PDF／PNG 出力には Chromium が必要
- スライドデッキのキャンバスでは、デッキのカード（ダブルクリックでスライドエディタを開く）の右に、各スライドの画像が横 4 枚ずつ並ぶ。画像はサーバーが Chromium で撮って `.canvcode/slide-pages/` に置き、デッキを保存するたびに変わったスライドだけ撮り直す。画像は固定されているので、上に付箋・フリーハンド・矢印などで書き込める
- スライドには id（Markdown の `# 見出し {#s-xxxxxx}`、JSON の `name`）が振られる。スライドを並べ替えたり足したりすると、画像は新しい位置へ移り、上に置いたもの（中心が画像の中にあるノード）も一緒に動く。デッキから消えたスライドの画像は消さず、上の書き込みごと並びの下に「デッキから削除されたスライド」として移す。自分で付けた name はそのまま id になる（変えると別のスライドとして扱う）
- Chromium は Playwright が入れたもの（`npx playwright install chromium`）を使う。ほかの Chrome／Chromium を使うときは、環境変数 `CANVCODE_CHROMIUM` に実行ファイルのパスを指定する
- 貼り付けた画像と取り込んだ PDF は `<ワークスペース>/.canvcode/assets/` に、中身の SHA-256 を名前にして保存される。PDF は検索用のテキストも `<ハッシュ>.pages.json` に取り出しておく
- File の id とパスの対応は `.canvcode/files.json`、完全に削除したファイルは `.canvcode/deleted/` に置く
- キャンバス・ノード・矢印のつながり・引用などのレコードは `.canvcode/workspace.db`（SQLite）、Portal のサムネイルは `.canvcode/thumbnails/` に保存される。操作するたびに少し待ってサーバーへ送る。右上に「保存済み」「保存中…」「未接続」が出る。サーバーが止まっている間の変更は、つながったら送る（タブを閉じると失われる）
- Canvas ごとの最後のカメラは、ブラウザ（端末ごと）に覚える
- 旧アプリ（recursive-infinite-canvas）の `.ricbackup` は、画面にドロップするか、VPS の上にあるなら `npm run import -- --workspace <フォルダ> <ファイル>` で取り込む（サーバーが動いていればサーバーに頼み、開いているタブにもすぐ届く）。ワークスペースが空なら旧のルートがそのままホームに、空でなければホームの下の「取り込み（日付）」に入る。ゴミ箱の中のものと AI 会話は取り込まない。元のファイルは `.canvcode/imports/` に残る
- バックアップはワークスペースのフォルダを丸ごとコピーすればよい。サーバーを動かしたままコピーするときは、先に `npm run snapshot -- --workspace <フォルダ>` で `workspace.db` の写し（`.canvcode/snapshots/`）を作る

VPS 上で動かし、手元の PC からは SSH のポートフォワードで開く。

```bash
ssh -L 8787:127.0.0.1:8787 <VPS>
# ブラウザで http://localhost:8787 を開く
```

Tailscale Serve から開く場合は、CanvCode のサーバーをその tailnet URL に限定して許可し、Serve は tailnet 内だけに公開する。アプリ自体にログイン機能はないので、tailnet のアクセス制御も確認する。

Tailscale 経由で本番サーバーを起動・再起動するときは、Serve が表示する HTTPS の Origin を毎回 `CANVCODE_TRUSTED_ORIGIN` に設定する。設定がないと Host / Origin の確認で API と画面の接続が拒否される。リポジトリのルートで実行する。

```bash
# package.json / package-lock.json が変わったとき
npm install

# 画面のコードを更新したとき（型チェックと dist のビルド）
npm run build

# tailscale serve status に表示される URL に置き換える
TAILNET_ORIGIN='https://machine.tailnet.ts.net'

# ログインシェルから切り離して起動し、ログを /tmp に保存する
setsid -f env CANVCODE_TRUSTED_ORIGIN="$TAILNET_ORIGIN" npm start >>/tmp/canvcode-main-server.log 2>&1 </dev/null

# 初回、または Serve の転送先を変更するときだけ設定する
sudo tailscale serve --bg 8787
tailscale serve status

# localhost と tailnet URL の両方で {"ok":true} が返ることを確認する
curl http://127.0.0.1:8787/api/health
curl "$TAILNET_ORIGIN/api/health"
```

`npm run build` は型チェックと Web 画面のビルドを行う。サーバーは `apps/web/dist` を配信するため、画面を変更したあとにビルドせず起動すると古い画面が表示される。サーバーの起動ログは `/tmp/canvcode-main-server.log` に出る。

開発時は `npm run dev`（Vite、http://127.0.0.1:5173）。ポートフォワードは `-L 5173:127.0.0.1:5173`。

```bash
npm test        # ユニットテスト（Vitest）
npm run lint    # oxlint
```

カード上のホイール・ドラッグの実ブラウザ回帰テスト（実際の CanvasView / CodeMirror とカメラ座標・各 DOM の scrollTop を確認）：

```bash
npx playwright install chromium firefox
npm run test:e2e                  # Chromium / Firefox、テスト用 Vite は自動起動
npx playwright install --with-deps webkit  # WebKit の OS 依存ライブラリが必要な環境のみ
npx playwright test --project=webkit
```

`apps/web/canvas-input-test.html` はネットワーク上のファイル保存だけをメモリに置き換えた専用ページ。失敗時のイベント経路とブラウザ trace は `test-results/` に出る。トラックパッド固有の OS ジェスチャーそのものは Playwright で再現できないため、細かい wheel 入力で代用する。

## AI から使う（MCP）

サーバーは `/mcp` で MCP（Streamable HTTP）を提供する。Claude Code などの MCP クライアントから、Markdown / Python の File の読み書きと、スライドデッキの作成・編集・確認ができる。書き込みは開いているタブにすぐ反映される（保存していない編集があるときは、いつもの衝突の確認が出る）。

```bash
# VPS 上、またはポートフォワードした手元の PC で
claude mcp add --transport http canvcode http://127.0.0.1:8787/mcp
```

| ツール | 内容 |
|---|---|
| `list_documents` | File の一覧（名前・パスで絞り込み） |
| `read_document` | 本文とハッシュを読む |
| `create_document` | 新しい File を作る（サイドバーの「未配置」に入る） |
| `update_document` | 本文を丸ごと置き換える（`expected_hash` で、読んだあとの変更を検出） |
| `edit_document` | 本文の一部を置き換える（スライドデッキでは、デッキとして読めない書き換えは断る） |
| `resolve_reference` | 画面で「AIに渡す」でコピーした `ref:` の ID を、場所と中身にする |
| `get_slide_format` | スライドデッキの書式（Markdown / JSON）・レイアウト・上限の説明と例 |
| `read_slide_deck` | デッキの本文・ハッシュ・スライドの一覧（番号・id・レイアウト・タイトル）・lint の警告 |
| `create_slide_deck` | 新しいデッキを作る（検証してから保存。id の無いスライドには id を振る。サイドバーの「未配置」に入る） |
| `update_slide_deck` | デッキを丸ごと置き換える（検証してから保存。`expected_hash` で、読んだあとの変更を検出） |
| `preview_slide_deck` | スライドを PNG の画像で返す（キャンバスと同じ画像。1 回に 8 枚まで。Chromium が必要） |

AI にスライドを頼むときは「canvcode でスライドを作って」のように言えばよい。AI は書式を読み、デッキを作り、警告を直し、画像で確かめる。作ったデッキはサイドバーの「未配置」からキャンバスへ置く。AI がデッキを書き換えると、キャンバスのスライドの画像も作り直される（id を保つので、上の書き込みはそのスライドに付いたまま）。

`/mcp` も `/api/` と同じく Host / Origin を確かめる。キャンバス上のノードの操作は、まだ提供していない。

### AI に見てほしい場所を渡す

範囲を選んで「AIに渡す」を押すと、`ref:XXXXXXXXXX` という ID がクリップボードに入る。それを Claude Code などに貼り付けると、AI が `resolve_reference` でその場所の中身を読む。ID は `.canvcode/workspace.db` に保存され、ブラウザで `/r/<ID>` を開くと、その場所に移る。ID は作ってから 3 日で、添えた画像と一緒に消える。

| 範囲 | 操作 |
| --- | --- |
| キャンバスの範囲 | 範囲選択（またはノードを選ぶ）→ 右クリックの「AIに渡すIDをコピー」（Ctrl+Alt+A） |
| Markdown / Python の行 | カードの上の編集・全画面のエディタで行を選び、「AIに渡す」 |
| PDF の範囲 | 「範囲を選んで引用」（Alt+ドラッグ）で囲み、「AIに渡すIDをコピー」 |

AI が受け取るのは、行ならそのときの本文（ファイルが変わっていれば探し直した位置）、キャンバスなら範囲の中のノード（カードは File の id を含むので `read_document` で読める）、PDF なら範囲の文字とページ全体の文字。

キャンバスの範囲選択で PDF のページの一部を囲むと（固定したページでもよい）、そのページのノードに `region`（ページの中の範囲と、その中の文字）が付く。囲んだ所が図や表など文字の少ない所なら、範囲の画像も添える（引用ツールから作る PDF の範囲も同じ）。

文書全体は応答に入れず、ファイルの絶対パスだけを付ける。AI は範囲の外まで読みたいときに、そのファイルを自分で読む。そのため AI は CanvCode のサーバーと同じマシンで動いている必要がある。

- Markdown / Python：`absPath` にファイルの絶対パスが入る（行の ref と、キャンバスの範囲の中のカード）。
- PDF：`textPath` に、PDF から取り出したテキストのファイル（`.canvcode/assets/<ハッシュ>.txt`）の絶対パスが入る。各ページは `=== page N ===` の行で始まり、PDF を読めないモデルでも読める。ファイルは PDF を読み込んだときに作る。それより前に読み込んだ PDF の分は、初めて ref を解決したときに作る。どのページにも文字がない PDF（スキャンした画像など）は、そのことを知らせる。

## 操作

| 操作 | 入力 |
| -- | -- |
| パン | ホイール、Space+ドラッグ、中ボタンドラッグ、手のひらツール |
| ズーム | Ctrl（⌘）+ホイール、トラックパッドのピンチ |
| 全体表示 | Shift+1 |
| パイメニュー | 「a」を押している間、ポインタの位置にツールのメニュー（選択 / 手のひら / フリーハンド / 消しゴム / 図形 › 矩形・楕円・フレーム・矢印 / 文字 › テキスト・付箋 / Portal › 空・PDF・Python・Markdown・スライド / Card › Python・Markdown）が出る。Portal › 空は Portal ツール、PDF は PDF を選んで取り込み、Python / Markdown / スライドは対応する File を置いたキャンバスと Portal を作る。Card › Python / Markdown はカードのツール。「.」はそのほか（元に戻す / やり直す / 計測の表示 / テスト用データ › / ベンチマーク ›）。「o」は操作（MAI-57）：今の選択とキャンバスに応じた項目だけが出る。PDF のページの Canvas では「次のページ」「前のページ」（倍率はそのままに、次のページの左上、または前のページの右下を画面に合わせる。今のページは画面の中心があるページ）と「ページをすべて選ぶ（固定を外す）」「ページを固定する」、テキストか付箋を選んでいれば「文字を大きく」「文字を小さく」「揃え ›」、2 つ以上を選んでいれば「整列 ›」、3 つ以上なら「等間隔 ›」、何かを選んでいれば「固定する」「複製」。項目が 1 つもなければ何も出ない。ポインタを項目へ向けてキーを離すと選ぶ（クリックでもよい）。› の付いた項目で離すと、次に押したときはその中の階層が出る。項目を選ぶ、別のパイメニューを開く、Esc のどれかで最初の階層に戻る。文字の入力中は出ない |
| 文字の編集 | ダブルクリック、または選択して Enter。Esc か Ctrl（⌘）+Enter、ほかの場所のクリックで終える |
| 文字の大きさと揃え | テキストか付箋を選ぶと、左端のパレットで文字の大きさ（A+ / A−）と、左揃え・中央揃え・右揃えを変えられる。複数を選んでいればまとめて変わる。編集中も使える |
| デザインパネル | ノードを選ぶと右上に出る（MAI-73）。塗り（図形・付箋）、線（図形・矢印・フリーハンドの色と太さ）、文字（テキスト・付箋の大きさ・色・揃え）、不透明度を変えられる。複数を選ぶと共通の項目だけが出て、値が違えば「混在」と出る。数字は Enter で確定（↑↓ で 1 刻み、Shift で 10 刻み）、ラベルを左右にドラッグしても変わる。スライダーや色の選択は、離すまでが Undo 1 回。Esc で入力をやめてキャンバスに戻る。× で閉じると「デザイン」のボタンだけになる（開け閉めはブラウザに覚える） |
| 文字の一部の書式 | テキスト・付箋は、文字の範囲ごとに色と大きさを変えられる（MAI-74）。編集中に文字を選んで、デザインパネルの「文字」の色・大きさを変えると、その範囲だけが変わる（パネルに入れても編集は続き、Enter で文字に戻る）。範囲を選んでいなければノード全体が変わる。選んだ範囲の値が違えば「混在」と出る。続けて打った文字は直前の文字の書式になる。編集中のコピー・貼り付けでも書式は残る。編集中の Ctrl+Z / Ctrl+Shift+Z は文字の編集だけを戻す・やり直す |
| フォント | テキスト・付箋のフォントを、デザインパネルの「文字」→「フォント」の一覧から選ぶ（MAI-75）。ゴシック（標準）・明朝・等幅と、同梱の M PLUS 1p、端末にある代表的な日本語・欧文のフォント（Local Font Access API が使えるブラウザでは「端末のフォントを追加」で端末のフォントすべて）。範囲を選んで編集中ならその範囲、そうでなければノード全体に当たる。Web フォントは読み込み終えてからレイアウトし直し、スライドの図・サムネイルなどの画像も読み込んでから描く |
| 箇条書き・番号付きリスト | テキスト・付箋の段落を箇条書き（• ◦ ▪ – ✓）や番号付き（1. 1) (1) a. i. ①）にできる（MAI-78）。編集中に段落の頭で「- 」「* 」「1. 」「1) 」と打つとリストになる（Ctrl+Z で打った文字に戻る）。Tab / Shift+Tab で階層を上げ下げし、階層ごとに記号が変わる（• ◦ ▪、1. a. i.）。Enter で次の項目、空の項目で Enter すると階層を上げ、一番外ならリストを抜ける。項目の頭で Backspace するとリストを外す。折り返した行は記号の後ろにそろう。番号は同じ階層・種類の段落が続く間だけ数え、リストでない段落が挟まると 1 に戻る。デザインパネルの「文字」→「リスト」「記号」で変えられる（範囲を選んで編集中ならその段落、そうでなければノードのすべての段落。記号は一番浅い階層の段落に当たる）。コピーするとほかのアプリには ul / ol で渡る |
| 太字・斜体・下線・取り消し線 | テキスト・付箋の文字を太字（B）・斜体（I）・下線（U）・取り消し線（S）にできる（MAI-79）。編集中は Ctrl（⌘）+B / I / U、Ctrl（⌘）+Shift+X か、編集中のテキストの上に出るツールバーのボタンで切り替える。デザインパネルの「文字」→「スタイル」のボタンでも変えられる。範囲を選んでいればその範囲（すべてオンならオフ、混在ならオン）、カーソルだけなら次に打つ文字に当たる（カーソルを動かすと取り消し）。編集していなければノードのすべての文字に当たる。範囲の文字が混在していれば、ボタンは点線の枠で出る。下線・取り消し線は折り返した行ごとに、文字の色・大きさに合わせて引く（行末の文字間の空き・リストの記号には引かない）。コピーするとほかのアプリには font-weight・font-style・text-decoration の style で渡る |

画面上部の「ベンチマーク」で、1 万ノードを置いた状態のパン・ズームのフレーム時間を測れる（MAI-14）。

### メモリーのベンチマーク（MAI-67）

```bash
npm run bench:memory                       # 画面をビルドしてから実行する
npm run bench:memory -- --canvases 10 --pdf-pages 20
```

使い捨てのワークスペース（一時フォルダ）でサーバーを起動し（既定のポートは 4188）、次の順に進める。本番のワークスペースには書き込まない。

1. ルートに Canvas を `--canvases` 個作る。それぞれに画像（`--images` 枚。1 枚目は 4000×3000 の JPEG）、PDF（`--pdf-pages` ページ。画像入りのページを含む）、Markdown の File（`--markdown` 個）を置く
2. ブラウザのコンテキストを作り直して開き直し、ルート → Canvas → その PDF → ルート … と巡回する
3. 移るたびに、画像を作り終えるまで待ってから GC し、JS ヒープ、プロセスごとの PSS（Linux のみ）、画面が持っているものの内訳（画像キャッシュ・サムネイル・開いている PDF・File の本文・Editor・レコード）を記録する

結果は `test-results/bench-memory/` に JSON と Markdown の表で出る。開いた Canvas の数に比例して増え続け、ルートに戻っても下がらないものが、上限のないキャッシュ（または漏れ）。Chromium は Playwright が入れたものを使う。ほかの Chromium を使うときは `CANVCODE_CHROMIUM` に実行ファイルのパスを指定する。`--keep` でワークスペースを残す、`--headed` で画面を出す。
